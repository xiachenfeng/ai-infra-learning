## 教学节奏

1. 先讲问题、对象和一个核心机制，再用小图或完整相关代码示范。
2. 讲解和图示示范占主要篇幅，允许连贯讲完一个因果链，不每讲一句就追问。
3. 先提供相似练习，再视表现安排一道独立变式；已理解时不重复机械练习。
4. 用户请求讲解时立即解释；提示后的正确回答不等于独立掌握。
5. 每单元完成独立应用检查；需要实机证据的结论另行验证。环境等待不阻止其余讲解。
6. 判断节奏是否改善，看完成同类应用任务是否更顺畅、间隔后能否解释和迁移，不以回复长度或答题数量衡量效率。

## R1 第一小节

- 关键认知：CPU 提交 GPU 工作与 GPU 完成工作是不同事件。
- 示例边界：数据已在 GPU；只讨论普通异步 kernel 提交的一种可能执行过程，不涉及数据复制、框架特殊同步或硬件真实耗时。
- 示范：准备 → 提交返回 → CPU 独立工作与 GPU 计算 → GPU 完成。
- 练习：提交计算后 CPU 输出“已提交”，能否据此判定 GPU 结果就绪？用户判断不能，核心正确，不评分。随后 5ms/20ms 时间线独立测评判断正确，未展开依据，已单独记录。
- 教学来源：[NVIDIA 编程模型](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html)、[异步执行](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html)。
