# Week 01 Learning Plan

- Week: 2026-08-01 至 2026-08-07
- Theme: GPU 执行模型入门
- Time budget: 3–4 小时
- Learning mode: 先理解原理，再动手观察

## Weekly Outcome

本周结束时，能够不查资料解释以下完整关系：

`CPU host → kernel launch → grid → block → warp → thread`

并能够运行一个最小 PyTorch GPU 程序，观察 GPU、显存和 kernel 执行信息。

## Session 1：建立执行模型（约 75 分钟）

### Goals

- 理解 CPU 与 GPU 的职责差异，以及 kernel launch 是异步的含义。
- 理解 grid、block、warp、thread 的包含关系。
- 理解 SIMT、warp size 和 warp divergence 的基本含义。

### Activities

1. 阅读一份 CUDA execution model 入门材料。
2. 手绘或复述执行层级图。
3. 回答：为什么 block 是调度与资源分配的重要边界？
4. 回答：同一个 warp 中出现条件分支可能产生什么影响？

### Evidence

- 用不超过 300 字写出自己的解释。
- 正确回答 4 道概念检查题。

## Session 2：观察 PyTorch GPU 执行（约 90 分钟）

### Environment

- 中国大陆按需 GPU 云实例
- 单卡 RTX 3090/4090 或同级 NVIDIA GPU
- 已配置 PyTorch 与 CUDA 的 Ubuntu 镜像

### Activities

1. 使用 `nvidia-smi` 确认 GPU、驱动和显存信息。
2. 在 PyTorch 中确认 CUDA 可用性和设备名称。
3. 分别在 CPU 和 GPU 上执行矩阵乘法并正确同步计时。
4. 改变矩阵规模，记录运行时间和峰值显存变化。
5. 观察异步执行导致的不正确计时，并加入同步操作进行对比。

### Evidence

- 保存命令、代码、环境信息和结果表。
- 能解释为什么 GPU 计时通常需要显式同步。
- 不以 CPU/GPU 单次快慢作为结论，说明启动开销和问题规模的影响。

## Session 3：复述与源码定位（约 45–60 分钟）

### Activities

1. 不查资料画出 GPU 执行层级。
2. 在 PyTorch 仓库或已安装源码中定位一个简单 CUDA 算子的入口。
3. 只追踪调用路径，不要求本周读懂 kernel 实现。
4. 记录遇到的 C++、CUDA 和框架术语。

### Evidence

- 给出至少一条“Python API → C++/CUDA 实现”的初步路径。
- 列出下周需要补充的 3 个前置概念。

## End-of-Week Check

在不查资料的情况下回答：

1. grid、block、warp、thread 分别是什么关系？
2. 为什么 warp divergence 会影响性能？
3. CUDA/PyTorch GPU 操作为何常表现为异步？
4. block 数量和每个 block 的 thread 数量由谁决定？
5. 为什么很小的计算放到 GPU 上可能更慢？

## Scope Guard

本周不展开 shared memory 优化、不编写复杂 CUDA kernel、不阅读论文，也不进入分布式训练。目标只是建立后续源码阅读所需的正确执行模型。
